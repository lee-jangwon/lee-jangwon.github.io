개발자는 평생 공부해야 하는 직업이다. 이는 그 누구도 무시하지 못할 명백한 사실이고, 이걸 받아들이지 못 한다면 도태되기 마련이다. 하지만 공부도 어디서부터 어떻게 공부하느냐를 잘 정한다면 평생 해야 할 공부가 더 편해지고 빠르게 이해될 수 있다. 기본 컴퓨터 과학 지식을 제대로 이해하고 있는 사람이 하는 공부와 그조차도 이해하지 못하지만 트렌드를 따라가는 공부를 할 수 밖에 없는 사람의 편차는 시간이 흐를수록 벌어지기 나름이다.

서론이 조금 길었지만 오늘은 컴퓨터 과학의 기본 중 할당, Copy, Deepcopy에 관해서 이야기해보려고 한다. 이전에도 메모리 관리에 대해서 다뤄본 적이 있지만 내가 아는 메모리는 컴퓨터 과학 분야에서는 너무나도 미세한 일부였고, 이번 기회에 제대로 배워보자.

## 변수 할당과 메모리 생성
파이썬은 고급 프로그래밍 언어(High Level Programming Language)로 개발자가 메모리에 대해서 자세하게 몰라도 언어를 나름 자유롭게 사용할 수 있다. 하지만 파이썬에서 변수를 생성한다는 건 정확하게 어떤 의미를 내포하고 있을까? 코드를 보며 같이 생각해 보자.
```python
my_name = "Lee Jang Won"
```
변수 `my_name`에 문자열 `"Lee Jang Won"`을 할당하는 과정에서 파이썬을 내부적으로 수행하는 몇 가지 주요 단계를 살펴보면 다음과 같다.

### 1. 객체 생성
- **문자열 객체 생성**: 파이썬은 `"Lee Jang Won"`이라는 데이터를 저장할 문자열 객체를 생성한다. 이 문자열 객체는 메모리 내에서 그 값과 함께 길이, 타입 정보 등 여러 가지 메타데이터를 포함하고 있다.

### 2. 메모리 할당
- **메모리 할당**: 생성된 문자열 객체를 위한 메모리가 할당된다. 파이썬은 문자열 같은 불변 타입의 경우, 동일한 문자열이 이미 메모리에 있을 때 이를 재활용하는 최적화를 수행할 수 있다. 그러나 새로운 문자열의 경우, 새로운 메모리 공간이 필요하다.

### 3. 변수 바인딩
- **이름과 객체 연결**: 변수 `my_name`은 생성된 문자열 객체를 가리킨다(참조; References). 이 바인딩 과정을 통해 `my_name`이라는 이름을 코드 내에서 사용할 때마다 파이썬은 연결된 객체를 참조하여 해당 문자열 데이터에 접근할 수 있다.

### 4. 참조 카운팅 및 가비지 컬렉션
- **참조 카운트 증가**: 객체에 대한 참조가 생성될 때, 해당 객체의 참조 카운트가 증가한다. 이 경우 `my_name` 변수가 새로운 문자열 객체를 참조하므로 참조 카운트는 1로 설정된다.
- **가비지 컬렉션**: 이후 변수 `my_name`이 다른 값으로 변경되거나 프로그램이 종료되면 이 객체에 대한 참조 카운트가 감소한다. 참조 카운트가 0이 된다면 파이썬 가비지 컬렉터가 해당 객체를 메모리에서 해제하여 리소스를 회수한다.

메모리가 어떻게 할당, 생성, 관리되는지 이해하는 것은 개발에 지대한 영향을 미친다. 특히 파이썬처럼 메모리를 동적으로 관리해 주는 메모리 관리자나 처리해 주는 가비지 컬렉터가 있는 경우에 메모리가 어떻게 동작하는지 제대로 이해하지 않고 코드를 작성할 경우, 의도치 않은 문제가 발생할 수 있으므로 더욱더 그렇다. 이제 메모리가 어떻게 할당되는지 알아봤으니, 조금더 심화한 내용을 살펴보자. 

## Copy와 Deepcopy
가끔 우리는 프로그램을 짤 때, 특정 흐름에서 생성된 리스트나 딕셔너리를 복사하거나 수정해야 할 일이 종종 발생한다. 그럴 때 만약 아래와 같이 단순히 `=`을 사용하면 어떻게 될까?
```python
a = [[1,2,3,],[4,5,6,],]
b = a
```
위 상황에서는 단순히 `b`가 `a` 리스트를 새로 가리킬 뿐이다. 따라서 `a`의 내용을 변경하게 된다면 `b`는 `a`를 그대로 가리키고 있기 때문에 `b`에도 의도치 않은 변화가 발생한다. 이런 동작을 의도했으면 괜찮겠지만, 의도하지 않았다면 매우 발견하기 어려운 논리 오류가 생긴다. 이런 의도치 않은 동작을 방지하기 위해서 `copy`와 `deepcopy`라는 걸 할 수 있다.

### 얕은 복사(Shallow Copy)
얕은 복사란 말 그대로 표면적인 내용만 복사하는 것을 의미한다. 위 예시를 들어 설명하면 최상위 컨테이너인 리스트 그 자체는 복사되지만, 그 안 내용물은 원본 객체와 동일한 참조를 공유하게 된다는 것이다. 말이 조금 복잡한 것 같으니, 예시를 확인해 보자.
```python
import copy

c = copy.copy(a)
```
얕은 복사와 깊은 복사는 자주 사용되므로 파이썬에서 표준 라이브러리 `copy`에서 찾아볼 수 있다. `copy.copy` 함수로 `c`는 `a`를 얕게 복사했다. 여기서 만약 `a`에 새로운 항목을 더하게(append) 된다면 어떻게 될까?

```python
a.append("이장원")
print(c) # [[1,2,3,],[4,5,6,],]
```
최상위 컨테이너를 참조가 아닌 복사했으므로 `c`는 의도했던 것과 같이 아무런 변화가 없다는 걸 확인할 수 있다. 하지만 만약 `a`의 첫 번째 항목을 수정한다면 `c`는 어떻게 될까?

```python
a[0].append("미장원")
print(c) # [[1,2,3,"미장원",],[4,5,6,],]
```
분명 `a`를 수정했음에도 불구하고 `c`에도 내용이 반영된 것을 확인할 수 있다. 위에서 말했던 최상위 컨테이너만 복사된다는 건 이런 현상을 말한다. 최상위 컨테이너인 가장 밖에 있는 리스트는 새로 만들었지만, 그 안에 들어있는 내용물은 아직 `a`와 동일한 객체를 가리키고 있다.

### 깊은 복사(Deep Copy)
그러면 이제 깊은 복사를 알아보자. 예상했겠지만 깊은 복사는 기존에 있던 객체와 그 객체 안에 있는 내용물까지 모두 새롭게 만들어서 복사하는 것을 의미한다. 깊은 복사를 하게 되면 복사된 데이터는 완전히 독립적인 객체가 되고, 원본 객체를 수정해도 복사된 객체에는 영향을 미치지 않는다.

```python
d = copy.deepcopy(a)
a[1].append("미장원 원장")
print(d) # [[1,2,3,"미장원",],[4,5,6,],]
print(a) # [[1,2,3,"미장원",],[4,5,6,"미장원 원장",],]
```

소프트웨어 개발에선 참 다양한 상황을 마주치기 나름이다. 어떨 때는 기본 설정을 가져오기 위해서 얕은 복사를 해야 할 때도 있고, 아예 데이터 변환 작업의 성능이나 효과를 비교하기 위해서 동일하지만, 새로운 객체가 필요할 수도 있다. 할당, Copy, Deepcopy의 특성을 잘 이해하게 된다면 시기적절하게 원하는 기능을 사용할 수 있을 것이다.

## 메모리 관리 및 최적화
이런 복사 기법을 이해하고 올바르게 사용하는 것은 메모리 사용을 최적화하고 의도치 않은 버그를 예방하는 데 중요하다. 파이썬에서 메로리를 효율적으로 관리하기 위해 다음과 같은 점을 고려할 수 있다.
1. **변경 가능성**: 데이터가 변경될 가능성이 있는지 고려하고 변경이 필요 없다면 불변 타입을 사용한다.
2. **메모리 사용**: 대규모 데이터 구조를 다룰 때는 메모리 사용량을 주의 깊게 모니터링하고 필요하지 않은 데이터는 적절히 삭제 및 최적화한다.
3. **가비지 컬렉션**: 파이썬의 가비지 컬렉터는 유용하지만 때로는 수동으로 객체를 삭제하거나 `gc`모듈을 사용해서 관리하는 것이 메모리 누수를 방지할 수 있다.

이렇게 메모리와 관련된 깊은 이해는 더 효율적이고 안정적인 소프트웨어 개발에 필수적인 역할을 한다. 파이썬 개발자로서 이러한 지식을 갖추는 건 코드가 더 나은 성능을 발휘하고 유지보수가 용이하도록 돕는다.

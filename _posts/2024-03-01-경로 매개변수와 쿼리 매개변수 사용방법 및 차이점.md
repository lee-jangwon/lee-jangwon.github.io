FastAPI를 공부하다 보면 자연스럽게 경로 매개변수(Path Parameter)와 쿼리 매개변수(Query Parameter)에 익숙해진다. 대부분의 튜토리얼이나 공식문서가 경로와 쿼리 매개변수를 어떻게 사용해야 하는지에 대해서는 자세하게 설명하지만, 차이점을 다루는 문서는 쉽게 찾아볼 수 없었다.

이 글은 내가 지금까지 무의식적으로 의지하던 경로 매개변수와 쿼리 매개변수를 간단하게 설명하고, 이 둘의 차이점을 정리한다.

## URL의 기본 구성
![URL components](https://developer.mozilla.org/ko/docs/Learn/Common_questions/Web_mechanics/What_is_a_URL/mdn-url-all.png)
> 사진 출처: [mdn web docs](https://developer.mozilla.org/ko/docs/Learn/Common_questions/Web_mechanics/What_is_a_URL)

경로 매개변수와 쿼리 매개변수를 설명하기 앞서, URL의 기본 구성부터 다시 알아보자. URL은 모두 프로토콜, 호스트, 포트, 경로, 쿼리, 부분 식별자(앵커)로 이루어진다. 프로토콜은 주로 `https` 또는 `http`같은 스키마를 뜻하고, 호스트는 도메인 주소가 어디인지 표시한다. 포트는 해당 서버의 요청을 받고 있는 포트 번호를 나타내고, 부분 식별자는 특정 웹 사이트에서 미리 정해진 섹션(Section)으로 갈 수 있게 해준다.

이제 남은건 우리가 관심 있었던 경로와 쿼리다. 경로는 서버에 있는 리소스의 위치를 나타낸다. 옛날에는 서버 컴퓨터의 파일 시스템에서 사용자가 찾고자 하는 파일이 어디에 있는지를 표시했지만, 요즘은 대부분 추상적으로 처리된다. 쿼리 매개변수는 웹 서버에 추가적으로 전달된다. 쿼리 매개변수는 서버에 있는 리소스를 필터링 할때 주로 사용된다.

## 경로 매개변수
이제 FastAPI에서 경로 매개변수를 제대로 알아보자.
```python
from fastapi import FastAPI
app = FastAPI()

@app.get("/items/{item_id}")
async def read_items(item_id: int):
    return {"item_id": item_id}
```
위 코드에서 경로 매개변수는 라우팅 문자열에서 중괄호 사이에 있는 `item_id`다. 위 URL 구성 요소에서 볼 수 있는 것처럼 경로 매개변수는 URL의 경로로 값을 전달한다. 중괄호 사이에 있는 내용이 변수명이 되고, 그 변수를 우리는 데코레이터로 포장된 함수에서 사용할 수 있다.

경로 매개변수는 이렇게 URL의 구성 요소로 쉽게 백엔드로 사용자가 인자를 넘길 수 있으므로 API 디자인에서는 필연적으로 사용된다. FastAPI의 경우 경로 매개변수 뒤에 타입 힌트를 제공하므로써 사용자가 제공하는 값에대한 검증도 진행할 수 있다. 추가로, FastAPI는 자동으로 공식문서를 만들어주기 때문에 타입힌트를 제공하면 공식문서에 예시가 더욱 올바르게 생성된다.

만약 자동으로 제공되는 인자 검증외에 추가 검증이 필요하다면 FastAPI의 `Path` 클라스를 사용할 수 있다.
```python
from fastapi import Path

@app.get("/items/{item_id}")
async def read_items(item_id: int = Path(gt=0)):
    return {"item_id": item_id}
```
위 코드는 기본적으로 제공되는 "인자는 정수여야 한다"라는 검증에 추가로 0보다 커야된다(gt; greater than 0)는 규칙을 추가적으로 반영한다.

## 쿼리 매개변수
FastAPI에서 쿼리 매개변수는 경로 매개변수와 유사한점이 매우 많다. 우선 코드를 살펴보자.
```python
@app.get("/items/")
async def read_items(skip: int = 0, limit: int = 10):
    return {"skip": skip, "limit": limit}
```
우선 보기에도 다른 점은 바로 라우팅 문자열에 별다른 변수 지정이 없다는 것이다. 위 URL 구성요소를 다시 보면, 쿼리는 URL의 주 리소스 위치 파악이 끝난 뒤, 부가적인 정보를 제공하는 것을 볼 수 있다. 쿼리는 물음표(?)로 시작되고, 키-값(Key-Value) 페어로 이루어진다.

라우팅 URL이 사선(`/`; forward slash)로 끝난다면 그 뒤에 물음표로 시작해서 `키`=`값` 형식으로 추가된다. 이렇게 추가되는 매개변수는 함수에서 사전 정의할 수 있고, 경로 매개변수와 마찬가지로 FastAPI의 `Query` 클라스로 추가 검증을 제공할 수 있다.

```python
from fastapi import Query

@app.get("/items/")
async def read_items(skip: int = Query(gt=0, default=0), limit: int = Query(gt=0, default=10)):
    return {"skip": skip, "limit": limit}
```

초기 FastAPI에서는 `Query` 클라스를 사용할 때 기본 값(default)를 지정하기 위해 많이 사용했지만, 요즘은 파이썬의 `typing` 모듈에서 `Annotated`를 가져와 사용한다. 예시는 아래와 같다.

```python
from fastapi import Query
from typing import Annotated

@app.get("/items/")
async def read_items(q: Annotated[str | None, Query(max_length=50)] = None):
    results = {"items": [{"item_id": "Foo"}, {"item_id": "Bar"}]}
    if q:
        results.update({"q": q})
    return results
```
`Annotation`은 해당 매개변수가 어떤 값을 가질 수 있는지 설명해주고, FastAPI의 `Query`를 사용해서 적절한 검증까지 제공한다. 이는 자동으로 생성되는 공식문서를 조금 더 깔끔하고 보기 쉽게 만들어주므로 기존 방식보다 더 권장된다.

## FastAPI - 경로 매개변수와 쿼리 매개변수의 차이점
사실 FastAPI의 공식문서만 훑어본다면 언제 경로 매개변수를 사용해야하고, 쿼리 매개변수를 사용해야 하는지가 명확하지 않다. 물론 쿼리 매개변수 섹션에서 보여준 검색(`q`) 예시처럼 쿼리 매개변수를 반드시 사용해야 하는 경우도 있지만, 애매한 경우가 있을 수 있다.

### 경로 매개변수를 사용할 때
경로 매개변수는 필수 사항으로써, 전통적으로 서버에 있는 리소스 위치를 파악하기 위해 사용됐다. 이는 즉 이미 존재하는 페이지, 목록, 항목 등을 조회할 때 사용된다는 것이다. 위 `items`를 예시로 들자면, `item_id`로 특정 항목을 불러올 때 사용할 수 있다. 사용자 아이디, 특정 범주, 특정 연도에 발표된 게시글 처럼 사용자가 자주 필요로 하는 내용을 보여줄 때 사용하는 것이 좋다.

### 쿼리 매개변수를 사용할 때
쿼리 매개변수는 경로 매개변수와 다르게 선택 사항이다. 그렇기 때문에 검색처럼 문자열 같은 부가적인 정보를 전달하기 위해 사용된다. 쿼리 매개변수는 하나의 리소스를 특정해서 반환하는 것이 아닌, 선택적 필터링, 정렬, 페이지 나눔(pagination)에 적합하다.
